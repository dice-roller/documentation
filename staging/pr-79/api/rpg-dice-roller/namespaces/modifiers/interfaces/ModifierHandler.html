Interface: ModifierHandler<N> ​

Defined in: src/modifiers/types.ts:29

The behaviour of a modifier.

Handlers are registered by name in the ModifierRegistry, and run in ascending order regardless of notation order; equal orders retain notation order. Implementations should not mutate their input: return a new array, copying changed items with the result helpers. Unchanged items may be reused.

groupHandling? ​

readonly optional groupHandling?: "flatten" | "each-pool"

Defined in: src/modifiers/types.ts:49

How the handler treats the dice inside a roll group. By default it only gets the members.

  • flatten: a group with a single expression gets the dice of every pool in it, flattened, instead of its member (keep, drop: {4d6+2d8}k2 keeps the 2 highest dice)
  • each-pool: gets the members of each group, then the dice of each pool, separately (sort: nested members are sorted by total, and the dice within each pool)

Pools in a pool's quantity or die arguments aren't included. Flattening stops at nested groups; with multiple expressions it operates on members instead. Flattened dice are written back to their original pools, so returned dice must retain their pool association (e.g. by copying an input item with object spread). New, unassociated dice cause an EvaluationError.

Defined in: src/modifiers/types.ts:58

Applies the modifier.

items are die results for a pool, or group members for a group (or die results, as set by groupHandling). Group calls, including calls for their pool dice, do not supply die or rollDie. The evaluator requires an array result.
