# Configuring rolls

The default settings are enough for most rolls, but you can supply options to change how dice are rolled, what values variables receive and how results are displayed.

## Passing options

Pass an options object as the second argument to `new Roll()` or the `roll()` shorthand. Pass options to a `Roller` constructor to share those settings across its rolls:

:::tabs key:roll-options variant:code

== Roll

```javascript
const result = new Roll('4d6', {
  limits: { maxQty: 100 },
});
```

== roll()

```javascript
const result = roll('4d6', {
  limits: { maxQty: 100 },
});
```

== Roller

```javascript
const roller = new Roller({
  limits: { maxQty: 100 },
});

const result = roller.roll('4d6');
```

:::

All options are optional:

| Option | Purpose |
| --- | --- |
| `engine` | [Choose the random-number engine](../customisation/random-number-generator.md). |
| `engines` | [Supply a registry of available random engines](../customisation/random-number-generator.md#register-a-custom-engine). |
| `drawDie` | [Supply finished die values](../customisation/external-dice.md) synchronously or asynchronously instead of using a random-number engine. |
| `dice` | [Supply a registry of dice definitions](../customisation/dice.md). |
| `modifiers` | [Supply a registry of modifier handlers](../customisation/modifiers.md). |
| `presenter` | [Choose how `present()` formats results](../customisation/presenters.md). |
| `limits` | [Set safety limits](#roll-limits) on quantities and repeating modifiers. |
| `data` | [Supply variable values](#variable-data) for notation. |

The built-in dice, modifiers, random engine and text presenter are used unless you supply alternatives. See the linked customisation guides for details.

A `Roller` shares its constructor settings across its rolls. Individual calls to `roller.roll()` can override **`engine`, `drawDie` and `data`**:

```javascript
const roller = new Roller({ data: { bonus: 3 } });

roller.roll('d20+$bonus');
roller.roll('d20+$bonus', { data: { bonus: 5 } });
```

These are per-roll overrides; they don't change the roller's defaults.

## Roll limits

The default safety limits are:

| Setting | Default | Purpose |
| --- | --- | --- |
| `maxQty` | `999` | Maximum number of dice in each set. |
| `maxIterations` | `1000` | Maximum extra batches for matching-batch explosion, generations per original die and modifier for explosion/re-roll, or retries per result for unique. |
| `maxGeneratedRolls` | `1000000` | Maximum number of additional dice generated by repeating modifiers within each dice pool. |

Override any of them in `limits` when creating a roll or roller:

```javascript
const result = new Roll('4d6', {
  limits: {
    maxQty: 100,
    maxIterations: 200,
    maxGeneratedRolls: 5000,
  },
});
```

All limit values must be positive safe integers.

`maxQty` applies separately to each set of dice, not to the whole expression. A limit of `100`, for example, allows `100d6+100d8`.

`maxIterations` applies to [matching-batch explosion](../notation/modifiers.md#matching-batch-explode), [explode](../notation/modifiers.md#explode), [re-roll](../notation/modifiers.md#re-roll) and [unique](../notation/modifiers.md#unique), including compound and penetrating explosions. A limit written in the notation, such as `d6!3`, uses the lower of that value and `maxIterations`.

`maxGeneratedRolls` counts additional dice rolled by repeating modifiers in one pool, including discarded re-rolls but excluding the initial dice. Once the budget is exhausted, the modifiers stop generating dice and keep the results reached so far rather than throwing for that limit. Each pool has its own budget; it also bounds branching rolls such as `d6!2:3`.

See [Repeating modifier limits](../notation/modifiers.md#repeating-modifier-limits) for how generation limits and multiple-die amounts work together.

## Variable data

Pass a `data` object to supply values referenced with `$name` in notation. Nested objects are supported:

```javascript
const data = {
  bonus: 3,
  character: { attackBonus: 2, isPoisoned: false },
};

const attack = new Roll('d20+$bonus', { data });
const otherAttack = roll('d20+$character.attackBonus', { data });
```

Here `$bonus` is `3` and `$character.attackBonus` is `2`. See the [variables notation guide](../notation/variables.md#variables-you-supply) for naming rules and references.

You can also provide defaults on a `Roller` and replace them for one roll:

```javascript
const roller = new Roller({ data });

roller.roll('d20+$bonus'); // Adds 3
roller.roll('d20+$bonus', { data: { bonus: 5 } }); // Adds 5
```

Per-roll `data` **replaces the whole default data object** rather than merging it. When you call `reroll()` without replacement `data`, it reuses the original roll's data snapshot:

```javascript
const strongerAttack = attack.reroll({ data: { bonus: 5 } });
```

Values must be finite numbers or booleans; `true` evaluates as `1` and `false` as `0`. A variable name must start with a letter or underscore and may then contain letters, numbers or underscores. Dotted paths follow the same rules, and capitalisation matters.

See [Rolling dice](index.md) for creating and re-rolling results, and the [notation guide](../notation/index.md) for expression syntax.
